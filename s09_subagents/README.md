# 09 · 把任务交给一个受限子代理

上一章：[技能](../s08_skills/README.md) · [课程目录](../README.md) · 下一章：[后台任务](../s10_background_jobs/README.md)

## 要解决的问题

父代理要读很多细节，却只需要一个短结论时，把所有原文放进父上下文很浪费。可以委派一个独立循环，但它不应自动继承父代理的全部历史和能力。

## 核心机制

[delegateTool](../lib/subagent.ts) 创建新的模型实例、工具注册表和 Session，只传递明确的任务文本。子代理只有 `read_file`，最多进行 4 次模型请求，最终只向父代理返回最多 2000 字符的文本。

```text
父会话：user → delegate_read(task) ─────────────────→ 简短结论 → final
                       ↓
子会话：        system → task → read_file → result → final
```

子代理工具表里没有 `delegate_read`，因此不能通过这个入口继续递归委派。调用沿用父请求的 `AbortSignal`，父请求取消会传到子循环和文件读取。

[code.ts](code.ts) 分别保存父、子 `ScriptedModel` 的请求记录，展示父输入不包含子代理的 `read_file` 调用。父输入只看到委派工具的结果，而非子代理全部过程。

上下文隔离不等于安全隔离：子代理仍在同一 Node 进程中运行。本课程也不持久化子会话到磁盘，因此不能拿父日志替代子代理的完整审计。

## 运行

```sh
npm run lesson -- 9
```

输出应包含：

```text
child tools: [ 'read_file' ]
parent sees child tool calls: false
```

最终答案来自固定脚本；请用请求记录确认工具隔离，而不是只看答案文本。

## 动手练习

1. 打印父子输入消息数，确认子代理没有继承父的整段会话。
2. 让子脚本调用 `delegate_read`，确认收到未知工具错误。
3. 给父请求传入已取消的 signal，确认子工具不继续读取。

完成标准：能列出委派传入的内容、子代理可用工具和返回父代理的内容。

## 与真实 dsh 的对应

官方支持更丰富的子代理生命周期、会话关联和不同执行提供方。本课程只有单层、同进程的受限委派，未实现团队消息、并行调度或独立进程。阅读入口见[源码对应表](../docs/official-map.md)。
