# 08 · 先发现，再加载技能

上一章：[上下文投影](../s07_context/README.md) · [课程目录](../README.md) · 下一章：[子代理](../s09_subagents/README.md)

## 要解决的问题

把每一种工作方法都塞进 system prompt，会让每次请求携带大量无关文字。但如果完全隐藏技能，模型又不知道什么时候可以使用。需要一个轻量发现入口，再按需读取详细内容。

## 核心机制

[skillTools](../lib/skills.ts) 暴露两个工具：

| 工具 | 输入 | 返回内容 |
|---|---|---|
| `list_skills` | 空对象 | 技能名字与适用场景 |
| `load_skill` | 精确的技能名字 | 对应 SKILL.md 文本 |

清单只登记一个 [source-reading](../skills/source-reading/SKILL.md) 技能，用来指导怎样阅读 dsh 源码。工具不能接收任意路径，技能名必须在固定清单中找到。返回文本同样受注册表输出上限约束。

本章的「加载」只意味着工具结果中出现技能文本，不改变系统权限，也不会自动执行其中的步骤。技能是供模型参考的内容，读取技能不能授予文件写权限；真正执行仍需工具与策略配合。

[code.ts](code.ts) 直接演示先发现后加载。第 11 章的脚本模型会按同样顺序请求两个工具，观察相应内容如何逐步进入上下文。

## 运行

```sh
npm run lesson -- 8
```

第一段输出只含 `source-reading` 名字与简介；第二段才出现完整 Markdown 指令。运行前模型不需要携带整个技能文件。

## 动手练习

1. 增加一个新的技能文件和清单条目，验证发现结果不包含技能正文。
2. 请求一个未登记名字，确认返回 `Unknown skill`，而不是尝试拼接任意文件路径。
3. 在第 11 章删除 `load_skill` 脚本响应，检查请求记录里不再出现技能全文。

完成标准：能指出内容从哪次工具结果进入请求，并说明为什么「可发现」与「已加载」是两件事。
